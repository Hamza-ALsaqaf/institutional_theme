## Calendar contrast (the !important text colour)
- Core `.fc-daygrid-dot-event { color: rgb(0,112,204) !important }` (calendar.scss:99).
- Original pairing: on `--ins-feedback-info-bg` Light #f0f8ff = 4.67:1 (pass); Dark #001f3a = 3.33:1 (FAIL). (COMPUTED)
- Fix: `html:root .fc-event { background-color: var(--ins-blue-50) }` (#f0f8ff, same in both modes, a primitive not a mode branch): 4.67:1 in Light and Dark. (COMPUTED)
- Finding: Frappe's calendar JS puts the colours INLINE on block events (`style="background-color: rgb(223,239,255)"`, `.fc-event-main style="color: rgb(0,88,149)"`), measured on the live page in en-dark. That pair is 6.34:1 (COMPUTED) and CSS cannot change it without !important. So the `.fc-event` background rule only reaches dot-style events, which did not render on this bench (the two test events render as blocks). The dot-event case is therefore COMPUTED, not rendered. Block events stay as light chips in Dark (visible in the screenshots).
- Dark grid lines: core forces `border-color: var(--gray-300) !important` (calendar.scss:36-43) and `--gray-300` is the bright end in Dark, giving near-white lines. Fixed without !important by re-pointing `--gray-300` to `--ins-border` on `.fc-theme-standard`. (VERIFIED in ar-dark screenshot, lines dim; the pre-fix en-dark screenshot shows them bright.)
