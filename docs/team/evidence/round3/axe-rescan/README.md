## Remaining violations, all core, with the reason and why the theme leaves them

| rule | nodes | where | cause (Frappe 16.32.0 / vendor) | why the theme leaves it |
|---|---|---|---|---|
| listitem | 220 | global search results (208), notifications tabs (12) | `ui/toolbar/awesome_bar.js:122-150` builds each result as `<li><a href>` inside awesomplete's `ul[role=listbox]` without `role="option"` (awesomplete's own `ITEM` has it, `node_modules/awesomplete/awesomplete.js:371-379`); `ui/notifications/notifications.js:88-94` writes `<li class="notifications-category">` under `ul[role=tablist]` | `role="option"` on the `li` removes `listitem`, `aria-allowed-attr` and `aria-required-children` but, tried by hand on the live search (axe run on the results after setting the attribute, English Light), `nested-interactive` fires on 52 nodes because each `li` holds a focusable `a`; `role="tab"` on the notification `li` promises keyboard behaviour (arrows, tabindex) that core does not implement. Neither is a safe attribute-only fix |
| meta-viewport | 48 | every desk page | `www/desk.html:14-15`: `maximum-scale=1.0, minimum-scale=1.0, user-scalable=no` | needs a core edit (a `<meta>` in the page head); no hook adds or removes it |
| aria-allowed-attr | 20 | search results (4 per language-mode, `li[aria-selected]`), workspace card menus (16, `a[aria-haspopup]` in `.card-actions`) | the `li` has no role (as above); the card-menu `a` has no `href`, no role, no tabindex | `role="button"` on a non-focusable `a` would be a name without an operable control; the real fix is core markup |
